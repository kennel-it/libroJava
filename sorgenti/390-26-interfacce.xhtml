definire punti di accesso comuni

La realtà che voglio modellare è formata tra gli altri da questi due oggetti: Squadra e Atleta. Quello che mi interessa di una squadra è il colore della maglia (cosa che non mi interessa degli atleti), in nome e il numero di telefono, di un Atleta mi interessa di nuovo il numero di telefono, il nome e il tempo migliore sui 100m.

Parte del mio programma prevede la posssibilità di visualizzare una rubrica che contenga sia le squadre che gli atleti: non mi interessa distinguere tra i due in questo contesto.

Proviamo a fare così: creo una classe InterfacciaRubrica con due metodi:

class InterfacciaRubrica {
	/* altri metodi e variabili */
    void visualizzaSquadra(Squadra s){
        campoNome.setText(s.getNome());
        ...
    }
    void visualizzaAtleta(Atleta a){
        campoNome.setText(a.getNome());
        ...
    }
}

E se in futuro esistessero altre entità che io vorrò visualizzare in InterfacciaRubrica? Come posso fare in modo che la mia interfaccia funzioni senza doverla stare sempre a modificare?

Per risolvere questo problema ci vengono in aiuto le interfacce. L'idea è questa: entrambe gli oggetti rappresentano una voce di rubrica e nel contesto di InterfacciaRubrica non ci interessa altro (non importa il tempo sui 100m per esempio). Possiamo esplicitare al livello sintattico questo concetto.

Dichiarazione di una interfaccia

Una interfaccia si dichiara in un file come una normale classe ma sostituendo class con interface.

Questa qui sotto è la nostra interfaccia:

public interface ElementoRubrica {
    public String getNome();
    public String getNumero();
}

Cosa ha di strano questo file?

i metodi sono publiclo possono essere come nelle classi manca il corpo dei metodi giusto! ma nelle interfacce i metodi sono fatti così.

Le interfacce a differenza delle classi non dicono come svolgere le azioni (cosa che nelle classi si fa nel corpo dei metodi) ma soltanto quali funzionalità un oggetto deve avere.

Implementazione di una interfaccia

Adesso dobbiamo dichiarare che il nostro Atleta si comporta anche come un ElementoRubrica: dobbiamo implementare l'interfaccia usando la parola chiave implements.

Un oggetto java può implementare più di una interfaccia, basta elencarle una dopo l'altra separandole con una virgola.

public class Atleta implements ElementoRubrica {
    private String nome;
    private String numero;
    
    /* tutti gli altri metodi */
    
    public String getNome() {
        return nome;
    }

    public String getNumero() {
        return numero;
    }
}

Il vantaggio a questo punto è questo: nella mia classe InterfacciaRubrica posso ignorare quale oggetto particolare devo visualizzare, mi interessa soltanto che implementi l'opportuna interfaccia ElementoRubrica.

class InterfacciaRubrica {
	/* altri metodi e variabili */
    void visualizzaSquadra(ElementoRubrica e){
	    campoNome.setText(e.getNome());
	    ...
    }
}

Se volessi implementare questa interfaccia anche nell'oggetto Allenatore la mia interfaccia grafica non avrebbe bisogno di nessuna modifica.

Una interfaccia non può:

  • essere direttamente instanziata cioè non posso creare un oggetto di tipo ElementoRubrica usando new perché nella definizione dell'interfaccia io non ho definito il suo comportamento (manca il corpo dei metodi).
  • avere variabili di istanza
