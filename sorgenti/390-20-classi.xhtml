Definire un oggetto

A questo punto abbiamo capito che un oggetto ha tipo class da java e che una classe va definita in un file che ha il suo stesso nome.

Osservando un po' i programmi che abbiamo scritto in precedenza possiamo osservare che senza saperlo abbiamo creato una classe. Nella dichiarazione c'è dell'altro che vedremo tra breve. Questa classe faceva un po' di tutto: disegnava e gestiva (al click del pulsante si aggiornava qualcosa scrivendo in qualche label o via dicendo) l'interfaccia grafica del programma, eseguiva tutti i calcoli necessari, ...

Con questo nuovo approccio avremo la classe che gestisce l'interfaccia e la classe che si occupa delle varie cose che abbiamo detto sopra.

Ogni singolo oggetto è composto da variabili (che mantengono lo stato di un oggetto) e da metodi (che definiscono cosa l'oggetto è in grado di fare).

Normalmente un programma è formato da più oggetti (organizzati in pacchetti) che interagiscono tra loro: il modo in cui un altro oggetto potrà interagire con quello che sto dichiarando lo definisco usando dei modificatori nelle dichiarazioni delle variabili e dei metodi.

Per un approfondimento vedi Controlling Access to Members of a Class

Esempio: Il risparmio vincolato

Quando otteniamo del denaro tra le possibilità che ci sono, oltre a spenderli tutti e subito, c'è quella di vincolarli per un periodo di tempo predeterminato (esempio: 3 mesi, 6 mei, 1 anno) sapendo sin dal momento del deposito e quindi del vincolo quale è la percentuale di interessi (guadagno) che avrò e da questa la somma in effetti guadagnata.

Quali sono le informazioni che caratterizzano un risparmio vincolato?
Innanzi tutto chi è il possessore di tale risparmio, quindi il nome ed il cognome. Segue il numero del risparmio vincolato che deve essere unico, la cifra vincolata, la percentuale di interessi garantita, la data di inizio del vincolo e la durata. Se vogliamo scrivere già queste informazioni otterremmo:

public class RisparmioVincolato {
   String nome;
   String cognome;
   int codice;
   double importo;
   short anno;
   byte mese;
   byte giorno;
   double interessiPercentuale;
}

Quali sono le informazioni che deve avere un oggetto appena si crea? Senza pensarci troppo, diremo che vogliamo la possibilità di dire niente all'inizio perché tutte le informazioni verranno impostate successivamente. Vogliamo però anche avere la possibilità di inserire tutte le informazioni al momento della creazione dell'oggetto. Per far ciò il linguaggio Java prevede il concetto di costruttore: un metodo particolare che dà un valore specifico a tutte le variabili.
Scavando nella memoria possiamo ricordare alcuni esempi come la dichiarazione di oggetti nei form come i pulsanti; infatti riprendendo la dichiarazione: Button pulsante = new Button() osserviamo che dopo il new c'è una invocazione di un metodo. La caratteristica è che tale metodo si chiama proprio come la classe. Ma si può fare anche la dichiarazione: Button pulsante = new Button("Premi qui") e anche questa volta abbiamo invocato un metodo che si chiama come la classe. L'unica differenza è che il primo metodo invocato non aveva argomenti, questo qui ha un argomento di tipo stringa. Quale è lo scopo dei 2 costruttori della classe Button? Probabilmente nel primo caso si vuole un pulsante senza testo e nel secondo caso si vuole un pulsante con del testo al suo interno.

La sintassi per creare dei costruttori è piuttosto semplice: NomeClasse(tipo argomento, tipo argomento, ...) { ... } e si vede già che a differenza dei metodi che conosciamo (esempi: start() e main()) non c'è un tipo restituito: né void, né int, né String.

La classe sopra con in più i costruttori sarà:

Ora si elencano le azioni (o funzionalità) che deve avere un qualunque oggetto di tipo RisparmioVincolato. La prima cosa che viene in mente è quella di sapere quanti soldi si guadagneranno allo scadere del periodo e anche quanti soldi si avranno in tutto (sempre alla scadenza del periodo). Affinché il metodo possa fornire il guadagno, numero con la virgola, restituirà un double per avre la massima precisione. Il metodo ha bisogno di argomenti? La risposta è no perché tutte le informazioni necessarie sono già memorizzate nelle proprietà della classe: l'importo ed il tasso (la percentuale) di interessi; discorso analogo per il capitale (cioè i soldi posseduti) totale.

public class RisparmioVincolato {
   private String nome;
   private String cognome;
   private int codice;
   private float importo;
   private short anno;
   private byte mese;
   private byte giorno;
   private float interessiPercentuale;

   /* Sono tutti valori scelti da me
    * senza nessun significato particolare
    * ma che chiaramente non possono
    * riferirsi ad alcun vincolo di risparmio
    * reale 
    */
   public RisparmioVincolato() {
      nome = "<indefinito>";		
      cognome = "<indefinito>";
      codice = 1;
      importo = 1.0;
      anno = 1970;
      mese = giorno 1;
      interessiPercentuale = 0.0;
   }

   public RisparmioVincolato(String n, String c, int cod, float euro, short a, byte m, byte g, float i) {
      nome = n;
      cognome = c;
      codice = cod;
      importo = euro;
      //Ci mettiamo anche un banale controllo sulle date: l'anno dal 1970 al 2025, il mese da 1 a 12, il giorno da 1 a 31
      if(a<1970) {
         a = 1970;
      } else if(a>2020) {
         a = 2025;
      }
      anno = a;
      if(m<1) {
         m = 1;
      } else if(m>12) {
         m = 12;
      }
      mese = m;
      if(g<1) {
         g = 1;
      } else if(g>31){
         g = 31;
      }
      giorno = g;
      interessiPercentuale = i;
   }

   public double fornisciGuadagno() {
      double guadagno = importo*interessiPercentuale/100; //formula per il calcolo degli interessi
      return guadagno;
   }

   public double fornisciCapitale() {
      double guadagno = fornisciGuadagno(); //anziché rifare il calcolo invochiamo il metodo
      double capitale = guadagno + importo;
      return capitale;
   }
}

Il programma sopra proposto ha un difetto: lascia alla classe Interfaccia la possibilità di interagire direttamente con le variabili interne alla classe. Nulla vieterebbe quindi che da qualche parte nella classe Interfaccia, si possa scrivere risparmio.giorno = 44; oppure risparmio.importo = -12.0;. Chiaramente sono errori.

Per prevenire tali situazioni possiamo impedire che alcune proprietà e/o metodi di una classe siano accessibili da altre classi. Potremmo e dovremmo ad esempio impedire che da qualsiasi altra classe diversa da RisparmioVincolato si possa accedere alle sue variabili (le proprietà).

Per definire se una variabile o un metodo sono visibili all'esterno dell'oggetto che stiamo definendo possiamo usare due modificatori: public e private. Se dichiaro qualcosa come private al difuori della classe non può essere usato, al contrario se lo dichiaro come pubblic in qualsiasi altra classe potrò usarlo; se non scrivo nulla sarà visibile soltanto dagli oggetti dello stesso pacchetto; vediamo più avanti cosa significa. Per ora concentriamoci sulle 2 parole chiave appena indicate.

Se rendiamo private tutte le proprietà di RisparmioVincolato, come si può fare ad impostare il capitale o la percentuale di interessi al di là del costruttore?
La soluzione è fornire dei metodi pubblici che impostano, dopo aver effettuato controlli di correttezza, le variabili private: sono i setters. Serviranno poi altri metodi che forniscono il valore di queste variabili private (ogni metodo ne fornisce una): sono i getters.

Facciamo l'esempio con la sola proprietà importo:

private float importo;

public void setImporto(float euro) {
   if(euro>0) {
      importo = euro; //Anche se la proprietà è privata, il metodo della stessa classe accede a tutte le variabili
   } else {
      importo = 0;
}

public float getImporto() {
   return Importo;
}

Eclipse può aiutarci nella generazione dei getters and setters: click col destro sulla classe nel Package Explorer o sullo sfondo nella finestra del sorgente quindi click sulla voce Generate getters and setters...
Nella finestra che si aprirà si scelgono i setters e getters per le singole proprietà o per tutte.

Una per tutti: le proprietà statiche

Riprendiamo l'esempio del risparmio vincolato. Abbiamo fatto i conti senza le tasse: sappiamo infatti che in tutti i tipi di risparmio lo Stato ci chiede una percentuale sull'intero capitale o sul guadagno. In questo esempio supponiamo che si debbano pagare le tasse sul capitale totale. Tali tasse saranno una percentuale o una quota fissa (ad esempio 5€) e in entrambi i casi tali tasse non sono diverse per i vari risparmi: il risparmio vincolato di Luca ha le stesse tasse del risparmio vincolato di Valentina e così via. A cosa serve allora una proprietà che si deve impostare sempre allo stesso valore per ogni oggetto creato?

Sarebbe senz'altro più comodo dire: tutti gli oggetti creati di tipo RisparmioVincolato condividono il fatto che ci sono tasse forfettarie (cioè fisse) e per tutti tali tasse sono uguali. Non ha allora significato dire che il risparmio di Luca ha tasse per 5€ perché lascia sott'intendere che tutti gli altri risparmi possono avere valori diversi. Quello che vogliamo dire è che tutti gli oggetti della classe RisparmioVincolato hanno tasse per 5€.
Quindi, ipotizzando di avere la proprietà private float tasse; e relativi metodi public void setTasse(float cifra) e public float getTasse():

RisparmioVincolato risparmiDiLuca = new RisparmioVincolato("Luca", "Pecci", 123321, 5000.0f, 2017, 10, 26, 0.005f);
risparmioVincolato.setTasse(5.0f);

lo consideriamo concettualmente sbagliato. Consideriamo invece corretta la proprietà private static float tasse; e osserviamo la nuova parola chiave static che significa appunto che non viene creata una variabile per ogni oggetto ma ce n'è una sola condivisa da tutti. I metodi potrebbero essere gli stessi riportati qualche riga più su ma noi vogliamo enfatizzare il fatto che quella proprietà è indipendente dal singolo oggetto e si riferisce piuttosto alla classe:

private static float tasse;

	public static float getTasse() {
		return tasse;
	}

	public static void setTasse(float t) {
		tasse = t;
	}

Quando nel programma si vuole utilizzare uno di questi due metodi, si dovrà utilizzare la forma RisparmioVincolato.getTasse() oppure RisparmioVincolato.setTasse(5.0f)

Un altro possibile utilizzo delle variabili statiche lo potremmo pensare sul numero del risparmio vincolato. Perché il numero lo dovremmo considerare come un progressivo che parte da 1 e ogni nuovo risparmio vincolato aggiungerà 1 al precedente. Per far questo è necessario mantenere memoria di quale sia stato l'ultimo valore assegnato per avere il nuovo numero corretto. Facilmente lo possiamo fare con la proprietà statica. In questo caso al costruttore non verrà dato il codice come argomento perché se lo calcolerà da solo:

public class RisparmioVincolato {
   private String nome;
   private String cognome;
   private int codice;
   private float importo;
   private short anno;
   private byte mese;
   private byte giorno;
   private float interessiPercentuale;
   private static int ultimoAssegnato = 1;
   private static float tasse;

   //Dato che devo fare la stessa cosa in 2 punti creo un metodo privato
   private boolean impostaDataCorretta(short a, byte m, byte g) { 
      if(a<1970) {
         a = 1970;
      } else if(a>2020) {
         a = 2025;
      }
      anno = a;
      if(m<1) {
         m = 1;
      } else if(m>12) {
         m = 12;
      }
      mese = m;
      if(g<1) {
         g = 1;
      } else if(g>31){
         g = 31;
      }
      giorno = g;
   }

   public RisparmioVincolato() {
      nome = "<indefinito>";		
      cognome = "<indefinito>";
      codice = ultimoAssegnato;
      ultimoAssegnato++;
      importo = 1.0;
      anno = 1970;
      mese = giorno 1;
      interessiPercentuale = 0.0;
   }

   public RisparmioVincolato(String n, String c, float euro, short a, byte m, byte g, float i) {
      nome = n;
      cognome = c;
      codice = ultimoAssegnato;
      ultimoAssegnato++;
      importo = euro;
      interessiPercentuale = i;
      impostaDataCorretta(a, m, g)
   }

   public void setNome(String nome) {
      this.nome = nome;
   }

   public String getNome() {
      return nome;
   }

   public void setCognome(String nome) {
      this.cognome = cognome;
   }

   public String getCognome() {
      return cognome;
   }

   public void setData(short a, byte m, byte g) {
      impostaDataCorretta(a, m, g);
   }

   public String getData() {
      String data = g+"/"+m+"/"+a;
      return data;
   }

   public double fornisciGuadagno() {
      double guadagno = importo*interessiPercentuale/100-tasse;
      return guadagno;
   }

   public double fornisciCapitale() {
      double guadagno = fornisciGuadagno();
      double capitale = guadagno + importo;
      return capitale;
   }

   public static float getTasse() {
      return tasse;
   }

   public static void setTasse(float t) {
      tasse = t;
   }

   public static int getUltimoCodiceUsato() {
      return ultimoAssegnato-1;
   }
}

Nella classe Interfaccia si può conoscere quale è stato l'ultimo codice assegnato invocando RisparmioVincolato.getUltimoCodiceAssegnato().

In definitiva esiste un modo per far sì che tutti gli oggetti della stessa classe condividano un valore: usare il modificatore static. La variabili e i metodi così definiti possono essere usati senza creare una istanza della classe cioè senza creare un oggetto con new, come ad esempio Math.PI o Math.sin() o anche Integer.parseInt(). Attenzione ad una cosa: i metodi static possono vedere soltanto le variabili static perché non facendo parte di una istanza di una classe non possono vedere le varibili di istanza (quelle non static) le quali vengono create, appunto, col new.

file it/esempi/Terzo.java

package it.esempio;

	public int w;
	String c;
	public Terzo(String u){
		c=u;
	}
	public String descrivi(){
		return c+x+c;
	}
}
