distribuzione

distribuire il prodotto finale all'utente

Ad un certo punto dopo aver fatto il programma bisogna darlo a chi ce lo ha chiesto... come?

Java è nato come linguaggio multipiattaforma e fin dall'inizio della sua storia la modalità per distribuire il software era quella di creare un file che gli utenti potessero eseguire su qualsiasi piattaforma soltanto avendo java installato. Questo approccio ha l'enorme vantaggio di permettere di avere un solo file che tutti coloro che hanno Java installato (su macOS, Linux o Windows) possono eseguire il programma. Ma tutti coloro che non hanno Java installato? La risposta è facile "lo installano".

Con l'arrivo di Java14 abbiamo però una alternativa in più: creare una applicazione che gira nativamente senza bisogno di avere Java installato. Questo grazie a nuovi strumenti e alla nuova licenza Open Source di Java.

jar

La modalità classica di creazione di un file da distribuire all'utente finale è quella di creare un "jar" cioè un file zip strutturato in una maniera particolare che contiene tutti i file .class che compongono il programma stesso più altri file utili alla sua esecuzione (ad esempio i file css o le immagini che abbiamo inserito).

Quando si fa doppio click cu uno di questi file zippati (che avranno ".jar" come estensione) su un computer con java installato viene automaticamente avviato java che a sua volta apre una specifica classe presente nel file.

La procedura per generare questo file dipende dall'ambiente di sviluppo utilizzato e include nel pacchetto creato tutte le classi presenti nel progetto.

Questo meccanismo un paio di problemi:

  • nel caso di javafx le librerie che usa dipendono dalla piattaforma (sarebbe a dire che su Windows servono alcuni file e ad esempio su Linux altri).
  • l'utente deve avere java installato (e di una versione almeno pari a quella che abbiamo usato per lo sviluppo)

Creare una configurazione di avvio

Se non ci sono esigenze particolari basta aprire la classe principale della nostra applicazione e avviarla almeno una volta.

Produrre il paccheto jar

  • click con il destro sul progetto
  • click sul menu "export..."
  • dal gruppo "Java" selezionare "Runnable JAR file", poi click su next
  • in "Launch configuration" selezionare la configurazione di avvio che lancia la nostra classe principale
  • selezionare la destinazione in "Export destination"
  • in "Library handling" la selezione redefinita "Extract required libraries into generated JAR" va normalmente bene (supponiamo che non si stiano usando librerie o che abbiamo diritto ad includere le librerie, fatto da controllare nella loro licenza)
  • click su "finish"

NetBeans ha un modo automatico per produrre questi particolari file zip (che avranno come estensione .jar) e per specificare quale è la classe che va avviata al doppio click.

Specificare la classe principale

Ogni progetto ha una classe che viene impostata da Netbeans al momento della sua creazione, in caso che serva di cambiarla:

  • click con il destro sul nome del progetto, poi click sul menu "Properties"
  • click sulla voce "Run"
  • la voce "Application Class:" dovrà contenere il nome della classe principale, può essere selezionata usando il tasto "Browse..."

Produrre il paccheto jar

  • click con il destro sul nome del progetto, poi click sul menu "Properties"
  • click sulla voce "Build" poi sub-voce "Packaging"
  • spuntare "Build JAR after compiling"
  • la voce "JAR File" ci dice dove verrà salvato il file jar all'interno della cartella del progetto

A questo punto ogni volta che un progetto viene compilato viene anche creato il file jar, se non serve l'opzione può essere disattivata.

jpackage

Dalla versione 14 di Java nel JDK esistono degli strumenti che permettono di creare un programma direttamente eseguibile senza bisogno di installare prima java.

Creare molteplici versioni (una per Mac, una per Linux e una per Windows) del programma non è difficile, basta crearlo su piattaforma seguendo lo stesso procedimento.

Siccome lo strumento è molto nuovo e versatile non ci sono ancora strumenti automatizzati comodi da utilizzare, non è però difficile fare le operazioni manualmente: l'unica richiesta è che per poter lavorare con Windows è necessario installare una versione di Bash (un interprete dei comandi molto comune sui sistemi Unix) e non va bene quello che fornisce Microsoft... per farla breve bastainstallare GIT e in automatico avremo anche GitBash che va bene per i nostri scopi.

vedi se serve ulteriore programma per windows

Per partire utilizziamo un caso quasi semplice: HelloWorld scritto con JavaFX. Il "quasi" è dovuto al fatto che usiamo una libreria (JavaFX) che non fa parte della distribuzione standard di Java.

Passo zero: creare la cartella "esportazione" sul Desktop.

Primo passo: far generare ad Eclipse un file jar del nostro progetto.

  1. Menu File/Export...
  2. selezionare gruppo "java" e poi voce "Jar File"
  3. "Select the resource project to export:" basta selezionare il progetto che interessa, helloWorld nel nostro caso (compare un "-" perché la cartella settings giustamente non viene esportata)
  4. spuntare "export generated class files and resources"
  5. nella voce "JAR file:" impostare "helloWorld.jar" nella cartella "esportazione" creata prima

Secondo passo: inserire nella cartella tutte le altre librerie che usiamo. QUesto è facile: basta andare nella cartella di javafx e copiare tutti i file (non la cartella stessa) della cartella lib in "esportazione".

Terzo passo: proviamo. Per farlo è semplice: aprire un terminale posizionarsi nella cartella Desktop. Poi scrivere:

/opt/jdk-14+36/Contents/Home/bin/java --add-modules javafx.controls,javafx.media,javafx.fxml \
--module-path esportazione -cp $(ls target/jars/*.jar |  tr '\n' ':') helloWorld.CiaoMondo

Se il programma non parte abbiamo fatto qualcosa di sbagliato. Cosa? dipende dal messaggio di errore.

Quarto passo: l'icona. Dobbiamo copiare sulla scrivania un file hello.icns (il tipo di file dipende dalla piattaforma icns va eben per macOS, png va bene per Linux) che è l'icona della nostra applicazione.

NB: la cartella "hello" non deve esistere sul desktop(nel caso di macOS dal Finder... l'applicazione "hello" non deve essistere).

/opt/jdk-14+36/Contents/Home/bin/jpackage --type app-image -n hello \
--icon hello.icns \
--input esportazione \
--module-path esportazione \
--add-modules javafx.controls \
--main-class helloWorld.CiaoMondo --main-jar helloWorld.jar
