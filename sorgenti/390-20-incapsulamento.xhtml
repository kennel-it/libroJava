Organizzare gli oggetti

Un paio di meccanismi ci consentono di tenere organizzati gli oggetti:

  • uno è il sistema di pacchetti che ci permette di raggruppare oggetti che hanno scopi simili in strutture analoghe alle cartelle
  • un altro (e più importante) sistema è quello che consente di specificare cosa gli altri oggetti possono vedere dell'oggetto che stiamo definendo

I modificatori public o private che vengono scritti prima del tipo nella dichiarazione delle variabili o dei metodi servono per definire se una proprietà (o un metodo) possono essere visti al di fuori dell'oggetto, una buona strategia generale è quella di evitare che gli altri oggetti possano modificare lo stato (cioè una delle proprietà) degli oggetti direttamente ma di creare appositi metodi che chiedano all'oggetto di modificare il suo stato. Doppio vantaggio:

Per un approfondimento vedi Controlling Access to Members of a Class
  • se decido di rappresentare diversamente lo stato interno di un oggetto ma lascio intatti i metodi pubblici non devo cambiare gli altri oggetti
  • se chi usa l'oggetto decide di impostare un valore errato si possono fare i controlli

Esempio: il risparmio vincolato

Quando otteniamo del denaro tra le possibilità che ci sono, oltre a spenderli tutti e subito, c'è quella di vincolarlo per un periodo di tempo predeterminato (ad esempio un anno) sapendo sin dal momento del deposito e quindi del vincolo quale è la percentuale di interessi (guadagno) che avrò e da questa la somma in effetti guadagnata.

Quali sono le informazioni che caratterizzano un risparmio vincolato?
Innanzi tutto chi è il possessore di tale risparmio, quindi il nome ed il cognome. Segue il numero del risparmio vincolato che deve essere unico, la cifra vincolata, la percentuale di interessi garantita, la data di inizio del vincolo (nel nostro caso il solo anno visto che i nostri importi sono vincolabili soltanto il primo gennaio). Se vogliamo scrivere già queste informazioni otterremmo:

file RisparmioVincolato.java

public class RisparmioVincolato {
   String nome;
   String cognome;
   int codice;
   double importo;
   short anno;
   double interessiPercentuale;
}

Quali sono le informazioni che deve avere un oggetto appena si crea? Senza pensarci troppo, diremo che vogliamo la possibilità di non dire niente all'inizio perché tutte le informazioni verranno impostate successivamente. Vogliamo però anche avere la possibilità di inserire tutte le informazioni al momento della creazione dell'oggetto: avremo bisogno di due costruttori.

Ricordiamo che la sintassi per creare dei costruttori è piuttosto semplice: NomeClasse(tipo argomento, tipo argomento, ...) { ... }.

La classe sopra con in più i costruttori sarà:

public class RisparmioVincolato {
   String nome;
   String cognome;
   int codice;
   float importo;
   short anno;
   float interessiPercentuale;

   /* Imposto tutti valori scelti da me senza nessun significato particolare
    * ma che chiaramente non possono riferirsi ad alcun vincolo 
    * di risparmio reale 
    */
   RisparmioVincolato() {
      nome = "<indefinito>";		
      cognome = "<indefinito>";
      codice = -1;
      importo = 0.0;
      anno = -1;
      interessiPercentuale = 0.0;
   }

   public RisparmioVincolato(String n, String c, int cod, float euro, short a, float i) {
      nome = n;
      cognome = c;
      codice = cod;
      importo = euro;
      // Ci mettiamo anche un banale controllo sulle date: l'anno dal 1970 al 2025, 
      // il mese da 1 a 12, il giorno da 1 a 31
      if(a<1970) {
         a = 1970;
      } else if(a>2020) {
         a = 2025;
      }
      anno = a;
      interessiPercentuale = i;
   }
}

Sarebbe utile che l'oggetto ci permetta di sapere quanti soldi si guadagneranno allo scadere del periodo e anche quanti soldi si avranno in tutto (sempre alla scadenza del periodo). Affinché il metodo possa fornire il guadagno, numero con la virgola, restituirà un double per avere la massima precisione. Il metodo ha bisogno di argomenti? La risposta è no perché tutte le informazioni necessarie sono già memorizzate nelle proprietà della classe: l'importo ed il tasso (la percentuale) di interessi; discorso analogo per il capitale (cioè i soldi posseduti) totale.

public class RisparmioVincolato {

    // stesse dichiarazioni di proprietà e costruttori dell'esempio sopra 

   public double fornisciGuadagno() {
      double guadagno = importo*interessiPercentuale/100; //formula per il calcolo degli interessi
      return guadagno;
   }

   public double fornisciCapitale() {
      double guadagno = fornisciGuadagno(); //anziché rifare il calcolo invochiamo il metodo
      double capitale = guadagno + importo;
      return capitale;
   }
}

Il programma sopra proposto ha un difetto: lascia alla classe InterfacciaGrafica la possibilità di interagire direttamente con le variabili interne alla classe. Nulla vieterebbe quindi che da qualche parte nella classe InterfacciaGrafica, si possa scrivere risparmio.anno = 44; oppure risparmio.importo = -12.0;. Chiaramente sono errori.

Per prevenire tali situazioni possiamo impedire che alcune proprietà e/o metodi di una classe siano accessibili da altre classi. Potremmo e dovremmo ad esempio impedire che da qualsiasi altra classe diversa da RisparmioVincolato si possa accedere alle sue variabili (le proprietà).

Per dichiarare se una variabile o un metodo siano visibili (e quindi anche modificabili) da parte di altri oggetti rispetto a quello che stiamo definendo possiamo usare due modificatori: public e private. Se dichiaro qualcosa come private al difuori della classe non può essere usato, al contrario se lo dichiaro come pubblic in qualsiasi altra classe potrò usarlo; se non scrivo nulla sarà visibile soltanto dagli oggetti dello stesso pacchetto. Per ora concentriamoci sulle 2 parole chiave appena indicate.

Se rendiamo private tutte le proprietà di RisparmioVincolato, come si può fare ad impostare il capitale o la percentuale di interessi al di là del costruttore?
La soluzione è fornire dei metodi pubblici che impostano, dopo aver effettuato controlli di correttezza, le variabili private: sono i setters. Serviranno poi altri metodi che forniscono il valore di queste variabili private (ogni metodo ne fornisce una): sono i getters.

Facciamo l'esempio con la sola proprietà importo:

private float importo;

public void setImporto(float euro) {
   if(euro>0) {
      importo = euro; //Anche se la proprietà è privata, il metodo della stessa classe accede a tutte le variabili
   } else {
      importo = 0;
}

public float getImporto() {
   return Importo;
}

Eclipse può aiutarci nella generazione dei getters and setters: click col destro sulla classe nel Package Explorer o sullo sfondo nella finestra del sorgente quindi click sulla voce Generate getters and setters...
Nella finestra che si aprirà si scelgono i setters e getters per le singole proprietà o per tutte.

Una per tutti: le proprietà statiche

Riprendiamo l'esempio del risparmio vincolato. Abbiamo fatto i conti senza le tasse: sappiamo infatti che in tutti i tipi di risparmio lo Stato ci chiede una percentuale sull'intero capitale o sul guadagno. In questo esempio supponiamo che si debbano pagare le tasse sul capitale totale. Tali tasse saranno una percentuale o una quota fissa (ad esempio 5€) e in entrambi i casi tali tasse non sono diverse per i vari risparmi: il risparmio vincolato di Luca ha le stesse tasse del risparmio vincolato di Valentina e così via. A cosa serve allora una proprietà che si deve impostare sempre allo stesso valore per ogni oggetto creato?

Sarebbe senz'altro più comodo dire: tutti gli oggetti creati di tipo RisparmioVincolato condividono il fatto che ci sono tasse forfettarie (cioè fisse) e per tutti tali tasse sono uguali. Non ha allora significato dire che il risparmio di Luca ha tasse per 5€ perché lascia sott'intendere che tutti gli altri risparmi possono avere valori diversi. Quello che vogliamo dire è che tutti gli oggetti della classe RisparmioVincolato hanno tasse per 5€.
Quindi, ipotizzando di avere la proprietà private float tasse; e relativi metodi public void setTasse(float cifra) e public float getTasse():

RisparmioVincolato risparmiDiLuca = new RisparmioVincolato("Luca", "Pecci", 123321, 5000.0f, 2017, 0.005f);
risparmioVincolato.setTasse(5.0f);

Lo consideriamo concettualmente sbagliato perché ogni oggetto ha una sua tassazione cosa he invece secondo il nostro modello non è vera (le tasse sono uguali per tutti gli importi). Consideriamo invece corretta la proprietà private static float tasse; e osserviamo la nuova parola chiave static che significa appunto che non viene creata una variabile per ogni oggetto ma ce n'è una sola condivisa da tutti. I metodi potrebbero essere gli stessi riportati qualche riga più su ma noi vogliamo enfatizzare il fatto che quella proprietà è indipendente dal singolo oggetto e si riferisce piuttosto alla classe:

private static float tasse;

	public static float getTasse() {
		return tasse;
	}

	public static void setTasse(float t) {
		tasse = t;
	}

Quando nel programma si vuole utilizzare uno di questi due metodi, si dovrà utilizzare la forma RisparmioVincolato.getTasse() oppure RisparmioVincolato.setTasse(5.0f) cioè si fa riferimento direttamente alla classe piuttosto che ad una sua istanza.

Un altro possibile utilizzo delle variabili statiche lo potremmo pensare sul numero del risparmio vincolato. Perché il numero lo dovremmo considerare come un progressivo che parte da 1 e ogni nuovo risparmio vincolato aggiungerà 1 al precedente. Per far questo è necessario mantenere memoria di quale sia stato l'ultimo valore assegnato per avere il nuovo numero corretto. Facilmente lo possiamo fare con la proprietà statica. In questo caso al costruttore non verrà dato il codice come argomento perché se lo calcolerà da solo:

versione finale di RisparmioVincolato.java

public class RisparmioVincolato {
   private String nome;
   private String cognome;
   private int codice;
   private float importo;
   private short anno;
   private float interessiPercentuale;
   private static int ultimoAssegnato = 1;
   private static float tasse;

   //Dato che devo fare la stessa cosa in 2 punti creo un metodo privato
   private boolean impostaDataCorretta(short a) { 
      if(a<1970) {
         a = 1970;
      } else if(a>2020) {
         a = 2025;
      }
      anno = a;
   }

   public RisparmioVincolato() {
      nome = "<indefinito>";		
      cognome = "<indefinito>";
      codice = ultimoAssegnato;
      ultimoAssegnato++;
      importo = 1.0;
      anno = 1970;
      interessiPercentuale = 0.0;
   }

   public RisparmioVincolato(String n, String c, float euro, short a, float i) {
      nome = n;
      cognome = c;
      codice = ultimoAssegnato;
      ultimoAssegnato++;
      importo = euro;
      interessiPercentuale = i;
      impostaDataCorretta(a)
   }

   public void setNome(String nome) {
      this.nome = nome;
   }

   public String getNome() {
      return nome;
   }

   public void setCognome(String nome) {
      this.cognome = cognome;
   }

   public String getCognome() {
      return cognome;
   }

   public void setData(short a) {
      impostaDataCorretta(a);
   }

   public String getDescrizione() {
      String d = "Importo di "+importo+" vincolato da "+nome+" "+cognome;
      return d;
   }

   public double fornisciGuadagno() {
      double guadagno = importo*interessiPercentuale/100-tasse;
      return guadagno;
   }

   public double fornisciCapitale() {
      double guadagno = fornisciGuadagno();
      double capitale = guadagno + importo;
      return capitale;
   }

   public static float getTasse() {
      return tasse;
   }

   public static void setTasse(float t) {
      tasse = t;
   }

   public static int getUltimoCodiceUsato() {
      return ultimoAssegnato-1;
   }
}

Nella classe Interfaccia si può conoscere quale è stato l'ultimo codice assegnato invocando RisparmioVincolato.getUltimoCodiceAssegnato().

In definitiva esiste un modo per far sì che tutti gli oggetti della stessa classe condividano un valore: usare il modificatore static. La variabili e i metodi così definiti possono essere usati senza creare una istanza della classe cioè senza creare un oggetto con new, come ad esempio Math.PI o Math.sin() o anche Integer.parseInt(). Attenzione ad una cosa: i metodi static possono vedere soltanto le variabili static perché non facendo parte di una istanza di una classe non possono vedere le varaibili di istanza (quelle non static) le quali vengono create, appunto, col new.
