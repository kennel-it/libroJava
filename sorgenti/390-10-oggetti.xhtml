Problema e soluzione

Partiamo con un esempio per comprendere il fatto. Vogliamo gestire una certa quantità di autoveicoli dei quali ci interessa la targa, il modello e quanti km riesce a fare con un litro di carburante. Bisogna anche dare la possibilità di aggiungere una nuova auto a quelle presenti e fare il calcolo di quanto spende l'automobilista se percorre una certa quantità di chilometri ipotizzando il fatto che il carburante usato costi 1,5€ al litro; ognuna di queste funzionalità saranno associate alla pressione di un rispettivo pulsante.
Come procediamo?
Dato che le automobili sono una quantità adotteremo un vettore. Di quale tipo sarà però il vettore? Se lo facciamo di tipo stringa in una data cella ci sarà o la targa o il modello; per quanto riguarda il consumo è utile un numero con la virgola. La soluzione che siamo in grado di fornire ci porterà allora ad usare 3 vettori: uno per la targa, uno per il modello ed uno per i consumi; ovviamente tutte le informazioni di un veicolo saranno registrate allo stesso indice per tutti e 3 i vettori.

L'approccio alla soluzione procede in modo tale che l'algoritmo di interazione con i 3 vettori sta immerso nel programma. Se cambiassimo qualcosa nella rappresentazione dei dati dovremo poi cercare riga per riga tutti i punti in cui andiamo a lavorare con i vettori degli autoveicoli. Finché il programma rimane corto si può fare ma nel momento in cui diviene centinaia di righe diventa improponibile: ci vuole tanto tempo per un'operazione noiosa e basta una svista per compromettere il funzionamento del software realizzato.

Alternative

Creare in "un posto a parte" tutte le dichiarazioni che coinvolgono le variabili inerenti l'autoveicolo e tutte le funzionalità che accedono a tali variabili. In nessun'altra parte del programma si possono cambiare o leggere tali variabili se non tramite quelle specifiche funzionalità previste nell'area appena indicata. In questo modo se qualcosa non va, il problema è solo nell'area ristretta in cui c'è la gestione delle variabili. Se bisogna cambiare qualcosa nelle variabili o nelle funzionalità, basta operare nel "solito" punto prima indicato.

Cosa cambia

La programmazione ad oggetti implica un nuovo modo di creare modelli per i programmi: poniamo maggiore enfasi sui singoli attori (gli oggetti) della realtà che andiamo a modellare. Nel momento in cui si crea l'oggetto si indicano certamente le sue caratteristiche o proprietà ma anche i modi o metodi che interagiscono con tali proprietà.

Nell'esempio appena sopra, una proprietà sarà targa (di tipo stringa), un'altra sarà modello (di tipo stringa) e l'ultima sarà KmAlLitro (di di tipo numerico con la virgola). Un esempio di metodo è quello che presa una targa, la confronta con quella dell'oggetto in esame e restituisce true o false a seconda che la targa corrisponda o meno.

Riferendoci all'esempio degli autoveicoli possiamo pensare che ci saranno più oggetti dello stesso tipo, ciascuno con i propri valori: tutti avranno una targa ma ciascuna targa sarà diversa dalle altre e via così per le altre proprietà. Nel momento in cui ne definisci le specifiche, fai una operazione unica per tutti gli oggetti di questa "categoria". Possiamo allora considerare questa come una classe di oggetti.
Proprio class è la parola chiave che si usa in Java.

Vediamo cosa cambia facendo un confronto tra due versione dello stesso programma: vogliamo mantiene un elenco di automobili con relativa targa e consumo, all'occorrrenza inserendo la targa e i km percorsi il programma deve dirci quanto spenderemmo con una specifica automobile.

La prima versione del programma non usa gli oggetti

File: Autoveicolo.java

public class Autoveicolo {
	String targa;
	String modello;
	double kmAlLitro;
	
	public Autoveicolo(String t, String m, double l){
		targa = t;
		modello = m;
		kmAlLitro = l;
	}
	
	public boolean confrontaTarga(String t) {
		return targa.equals(t);
	}
}

public class Programma extends Application{
	
	String targa[];
	String modello[];
	double kmAlLitro[];
	Autoveicolo automobili[];
	int autoRegistrate = 0;
	
	TextField inTarga = new TextField();
	TextField inModello = new TextField();
	TextField inLitri = new TextField();
	TextField calcTarga = new TextField();
	TextField calcKm = new TextField();
	Label risposta = new Label();
	
	@Override
	public void start(Stage primaryStage) throws Exception {
		Button aggiungi = new Button("aggiungi auto");
		Button calcolaSpesa = new Button("calcola spesa");
		GridPane gp = new GridPane();
		gp.add(new Label("targa:"),0,0);
		gp.add(inTarga,1,0);
		gp.add(new Label("modello:"),0,1);
		gp.add(inModello,1,1);
		gp.add(new Label("consumo:"),0,2);
		gp.add(inLitri,1,2);
		gp.add(aggiungi,1,3);
		gp.add(new Label("targa:"),0,4);
		gp.add(calcTarga,1,4);
		gp.add(new Label("km:"),0,5);
		gp.add(calcKm,1,5);
		gp.add(calcolaSpesa,1,6);
		gp.add(new Label("spesa:"),0,7);
		gp.add(risposta,1,7);
		
		Scene scena = new Scene(gp);
		primaryStage.setScene(scena);
		primaryStage.setTitle("automobili");
		primaryStage.show();
		
		aggiungi.setOnAction(e->aggiungiAuto());
		calcolaSpesa.setOnAction(e->azioneSpesa());
		// ci prendiamo una licenza: non ci saranno mai più di 100 automobili
		targa = new String[100];
		modello = new String[100];
		kmAlLitro = new double[100];
		automobili = new Autoveicolo[100];
	}
	
	public static void main(String args[]){
		launch(args);
	}
	
	private void aggiungiAuto(){
		String t = inTarga.getText();
		String m = inModello.getText();
		double l100k = Double.parseDouble(inLitri.getText());
		
		targa[autoRegistrate] = t;
		modello[autoRegistrate] = m;
		kmAlLitro[autoRegistrate] = l100k;automobili[autoRegistrate] = new Autoveicolo(t, m, l100k);
		autoRegistrate++;
		risposta.setText(t+" registrata");
	}
	
	private void azioneSpesa(){
		String t = calcTarga.getText();
		double kilometri = Double.parseDouble(calcKm.getText());
		int trovato = -1;Autoveicolo trovata = null;
		double spesa;
		
		for(int i=0;i<autoRegistrate;i++){
			if(targa[i].equals(t)) {
				trovato=i;
			}if(automobili[i].confrontaTarga(t)) {
				trovata = automobili[i];
			}
		}
		if(trovato!=-1) {
			spesa = kilometri/kmAlLitro[trovato]*1.5;
			risposta.setText("l'automobile "+modello[trovato]+" spende "+spesa );
		}
		if(trovata!=null) {
			spesa = kilometri/trovata.kmAlLitro*1.5;
			risposta.setText("l'automobile "+trovata.modello+" spende "+spesa );
		}else{
			risposta.setText("non trovo "+t);
		}
		
	}
	
}

La seconda versione usa invece un oggetto: Autoveicolo con le proprietà marca, modello e kmAlLitro mentre i metodi sono: un costruttore (lo vedremo nel capitolo dedicato alle classi) e confrontaTarga().

Osserviamo che avremmo potuto dichirare più oggetti di tipo Autoveicolo anziché uno, per esempio per dichiarare 2 oggetti Autoveicolo scriveremo nel programma
Autoveicolo auto1 = new Autoveicolo();
Autoveicolo auto2 = new Autoveicolo();
È chiaro che ognuna delle 2 auto avrà la sua marca, il suo modello, i suoi km al litro che percorre ma se ci soffermiamo un istante appare chiaro che sebbene i valori saranno molto probabilmente diversi, è anche vero che tutte e 2 le auto hanno la proprietà marca, la proprietà modello e la kmAlLitro così come entrambe hanno i 2 metodi visti più in alto; nessuno dei 2 avrà però la proprietà maxVelocità perché non è stata sopra dichiarata.

In definitiva concludiamo che le caratteristiche di Autoveicolo le definiamo una volta e valgono per tutti gli oggetti di quel tipo che si vanno a creare e tali caratteristiche si esplicitano dichiarando la costruzione di una nuova classe che costituirà quindi il tipo degli oggetti.

In java ogni nome di classe inizia per maiuscola e deve essere registrata in un file che ha il suo stesso nome.
