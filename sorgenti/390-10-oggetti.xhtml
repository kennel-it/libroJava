dalla programmazione procedurale a quella ad oggetti

Il problema

Vogliamo gestire una certa quantità di autoveicoli dei quali ci interessano alcuni dati: la targa, il modello e quanti km riesce a fare con un litro di carburante, fornendo poi la llunghezza di un percorso vorremmo sapere quanto si spende con un determinato autoveicolo (supponendo che il carburante costi 1,5€ al litro).

Il nostro programma dovrà consentire all'utente di inserire diversi autoveicoli (al massimo 100) e in base alla targa e alla distanza calcolare la spesa del percorso.

Possibile soluzione

Dato che gli autoveicoli potrebbero essere una molti useremo un vettore, visto che però le informazioni da registrare sono almeno tre (targa, modello e km/l) saremo costretti ad usare tre vettori: uno di stringhe per la targa, un altro di stringhe per il modello ed uno di double per i consumi. Ovviamente tutte le informazioni di un veicolo saranno registrate allo stesso indice per tutti e 3 i vettori.

Quella mostrata qui sotto è una possibile soluzione.

public class Programma extends Application{
    String targa[];
    String modello[];

        gp.add(new Label("consumo:"),0,2);
        gp.add(inLitri,1,2);
        gp.add(aggiungi,1,3);
        gp.add(new Label("targa:"),0,4);
        gp.add(calcTarga,1,4);
        gp.add(new Label("km/l:"),0,5);
        gp.add(calcKm,1,5);
        gp.add(calcolaSpesa,1,6);
        gp.add(new Label("spesa:"),0,7);
        gp.add(risposta,1,7);
        
        Scene scena = new Scene(gp);
        primaryStage.setScene(scena);
        primaryStage.setTitle("automobili");
        primaryStage.show();
        
        aggiungi.setOnAction(e->aggiungiAuto());
        calcolaSpesa.setOnAction(e->azioneSpesa());
        // ci prendiamo una licenza: non ci saranno mai più di 100 automobili
        targa = new String[100];
        modello = new String[100];
        kmAlLitro = new double[100];
    }
    
    public static void main(String args[]){
        launch(args);
    }
    
    private void aggiungiAuto(){
        String t = inTarga.getText();
        String m = inModello.getText();
        double km = Double.parseDouble(inLitri.getText());
        
        targa[autoRegistrate] = t;
        modello[autoRegistrate] = m;
        kmAlLitro[autoRegistrate] = km;
        autoRegistrate++;
        risposta.setText(t+" registrata");
    }
    
    private void azioneSpesa(){
        String t = calcTarga.getText();
        double kilometri = Double.parseDouble(calcKm.getText());
        int trovato = -1;
        double spesa;
        
        for(int i=0;i<autoRegistrate;i++){
            if(targa[i].equals(t)) {
                trovato=i;
            }
        }
        if(trovato!=-1) {
            spesa = kilometri/kmAlLitro[trovato]*1.5;
            risposta.setText("l'automobile "+modello[trovato]+" spende "+spesa );
        }else{
            risposta.setText("non trovo "+t);
        }
        
    }
    
}

Programmazione ad oggetti

Quello che ci proponiamo di fare è di spostare l'attenzione dal "come fare le cose" (programmazione procedurale) al "modellare gli oggetti" (programmazione ad oggetti).
La domanda a cui dobbiamo rispondere nel nostro caso è: "cosa è un Autoveicolo?". E con questo intendiamo sia "cosa caratterizza una autoveicolo" che "quali azioni possiamo fare con una autoveicolo".

Visto quanto abbiamo detto finora per noi un Autoveicolo è un un oggetto che:

  • ha una targa (caratteristica)
  • ha un modello (caratteristica)
  • ha un certo consumo, misurato in km al litro (caratteristica)
  • può calcolare quanto andremo a spendere dato un numero di km (azione)

Java ci permette di modellare la realtà in questo modo usando le classi. Abbiamo già usato le classi ma fino a questo momento abbiamo creato programmi composti da una sola classe, quello che succede di solito invece è avere più classi che usate insieme ci permettono di costruire un programma modellando la realtà come un insieme di oggetti.

Questo approccio porta alcuni vantaggi che diventano sempre più evidenti all'aumentare della dimensione del programma che si sta trattando. Un possibile vantaggio è il fatto che possiamo concentrare in un unico punto tutta la rappresentazione di un oggetto (l'autoveicolo dell'esempio), questo ci consentirà in futuro di poter cambiare il nostro modello intervenendo in un punto unico del programma, oltre a ciò quando più sviluppatori lavorano sullo stesso progetto possono occuparsi di oggetti diversi riducendo la possibilità di interferire l'uno con l'altro.

Come cambia il programma

La prima cosa evidente è che anziché un singolo file ne avremo due: uno per l'interfaccia grafica e uno che rappresenta l'Autoveicolo, la cosa che ci interessa di più in questo contesto è questo ultimo.

Un oggetto in java si definisce usando la parola chiave class seguita dal nome dell'oggetto stesso e da un blocco di codice racchiuso tra parentesi graffe, al loro interno è possibile trovare dichiarazione di proprietà o metodi che riguardano l'oggetto stesso. Spesso ci si riferisce all'insieme dei valori delle proprietà di un oggetto come al suo stato.

Una classe Java va dichiarata in un file che ha lo stesso nome della classe.

Le proprietà sono usuali dichiarazioni di variabili fatte al livello di classe e i metodi sono delle funzioni che possono far riferimento alle proprietà dell'oggetto.

Un particolare metodo è quello che viene usato quando costruiamo una nuova istanza di nuovo oggetto: il costruttore che si riconosce perché ha lo stesso nome della classe e nessun tipo ritornato (non c'è scritto void, è proprio assente). Soltanto se non si definisce nessun costruttore nella classe java ne definisce uno predefinito che non accetta nessun parametro.

Quale è un possibile costruttore per la classe Tavolo?

public int calcola(int a, int b){...} non si chiama come la classe e ritorna un valore di tipo int public void Tavolo(){...} void non deve essere presente public Tavolo(){...} giusto, un costruttore senza parametri public Tavolo(int gambe){...} giusto, un costruttore che vuol sapere quante gambe ha il tavolo

Scrivendo una classe definiamo come si comporta un qualsiasi oggetto di quel tipo (in java definendo nuove classi si definiscono nuovi tipi) ma in realtà non costruiamo nessun oggetto. Per costruire un oggetto, operazione che formalmente si chiama creazione di una istanza si usa l'operatore new che crea un nuovo oggetto in memoria con tutte le proprietà associate, ovviamente ogni oggetto creato avrà le sue proprietà distinte dagli altri.
Possiamo a questo punto rivedere una riga di codice che abbiamo scritto molte volte: l'operatore new si usa scrivendo dopo di lui il costruttore di un oggetto come ad esempio in Button pulsante = new Button().
La parte a destra dell'uguale è quella che ci interessa: l'operatore new è seguito dalla chiamata di uno dei costruttori dell'oggetto Button, in particolare in questo caso uno senza parametri.
Ma si può scrivere anche la dichiarazione: Button pulsante = new Button("Premi qui") e anche questa volta abbiamo invocato un metodo che si chiama come la classe. L'unica differenza è che il primo metodo invocato non aveva argomenti, questo qui ha un argomento di tipo stringa. Quale è lo scopo dei 2 costruttori della classe Button? Avere modi diversi per creare dei Button (sono tre), chi ha scritto la classe ha deciso in quali modi sia possibile instanziarla, possiamo ipotizzare che nel primo caso si vuole un pulsante senza testo e nel secondo caso si vuole un pulsante con del testo al suo interno.

Quando usiamo l'operatore new stiamo creando nuove istanze di un oggetto: Button è in nome di una classe ( e quindi di un tipo ) ma poi pulsante o pulsanteCalcola o pulsanteCancella potrebbero essere due sue istanze.

Ogni istanza di una classe avrà le stesse proprietà ma con valori diversi, per accedere a queste proprietà (o anche ai metodi) si usa la notazione punto: se voglio accedere ad una proprietà di un oggetto scrivo il nome di una istanza seguita dal punto e dal nome della proprietà (o del metodo) che si vuole usare. Posso ad esempio cambiare il testo contenuto in un pulsante scrivendo pulsante.setText("pluto").

Riferendoci all'esempio degli autoveicoli possiamo pensare che ci saranno più oggetti dello stesso tipo, ciascuno con i propri valori: tutti avranno una targa ma ciascuna targa sarà diversa dalle altre e via così per le altre proprietà.

La nuova versione ad oggetti usa un oggetto: Autoveicolo con le proprietà marca, modello e kmAlLitro mentre i metodi sono: un costruttore un altro per calcolare il costo di un percorso.

	public double costoPercorso(double numeroKilometri) {
		return numeroKilometri/kmAlLitro*1.5;

me stesso

Capita a volte che all'interno di un metodo in una classe serva di far riferimento all'oggetto stesso, in questo caso è possibile usare la parola chiave this che indica appunto l'oggetto corrente. Perché mai dovrebbe servire? In generale per evitare di far confusione tra i nomi delle proprietà e i nomi dei parametri dei metodi.

Proviamo a vedere come è possibile riscrivere il costruttore del nostro Autoveicolo

File: Autoveicolo.java aggiornato

public class Autoveicolo {
    String targa;
    String modello;
    double kmAlLitro;
    
    public Autoveicolo(String t, String m, double l){
        targa = t;
        modello = m;
        kmAlLitro = l;
    public Autoveicolo(String targa, String modello, double kmAlLitro){
        // copio il valore della variabile targa passata al costruttore 
        // nella proprietà "targa" di questo oggetto
        this.targa = targa;
        this.modello = modello;
        this.kmAlLitro = kmAlLitro;
    }
}

Dopo un possibile senso di confusione iniziale il costruttore che usa this è più chiaro da leggere rispetto a quello che non usa this.
